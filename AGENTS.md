# CoreFit — Agent Instructions

## Project

CoreFit is a gamified fitness application that helps users track workouts, monitor progress, achieve goals, and earn rewards.

Main features include workout logging, exercise history, personal records, XP, levels, ranks, achievements, streaks, and challenges.

Premium features may include personalized workout schedules, advanced analytics, and an AI Coach.

## Communication

- Respond in Italian unless requested otherwise.
- Be concise, direct, and professional.
- Prioritize results over lengthy explanations.
- Avoid repetitive summaries and unnecessary commentary.
- For complex tasks, give a short plan and clear progress updates.
- Explain technical decisions only when they are relevant.

## Development

- Inspect existing code before making changes.
- Follow the current project architecture and conventions.
- Prefer simple, readable, and maintainable solutions.
- Avoid unnecessary abstractions, excessive dependencies, and overengineering.
- Reuse existing components and utilities when appropriate.
- Keep changes focused on the requested task.
- Do not refactor unrelated code without a clear reason.
- Do not introduce Firebase or Firebase-related services.
- Do not assume a framework or backend that has not been selected.
- Never hardcode credentials or expose sensitive user data.

## UI and UX

- Prioritize a modern, consistent, and responsive interface.
- Design for both desktop and mobile devices.
- Keep navigation intuitive and interactions accessible.
- Reuse design tokens and UI components.
- Avoid unnecessary animations and visual clutter.
- Maintain a consistent premium-quality visual identity.

## Product Logic

- Keep workout tracking and progress calculations reliable.
- Make XP, achievements, and reward logic consistent and testable.
- Separate free and Premium capabilities cleanly.
- Do not present planned features as implemented.
- Avoid unnecessary complexity in AI features.

## Quality

- Handle loading, empty, and error states.
- Validate user inputs.
- Add or update relevant tests for meaningful logic changes.
- Run available checks before reporting completion.
- Never claim that tests passed unless they were executed.

## Completion

Report:

1. What changed.
2. What was verified.
3. Any remaining issues or necessary next actions.

Keep the final report short.
